# 评审清单

这份文件是评审入口：左边是已经定下的架构决策，右边是仍然开放的产品选择。评审时只动这里，不动规范正文；定一条就在这里改一条，并把结论同步到对应文档。

## 1. 已定决策

| # | 决策 | 结论 | 备选 | 代价 |
| --- | --- | --- | --- | --- |
| D1 | 仓库划分 | `dsh-pet-market`（插件 + 格式规范）、`dsh-pet-index`（静态目录）、`dsh-pet-pack-template`（作者模板 + CI）、宠物宿主独立仓库 | 单仓多包 | 四个仓库要对齐版本 |
| D2 | 后端 | 零后端：无账号、无服务器、无托管、无审核队列 | 自建 API + 对象存储 | 受 GitHub 限流；发现依赖目录 PR |
| D3 | 内容边界 | 只校验格式与可运行性，不审内容 | 人工审核 | 市场不背书内容 |
| D4 | 格式范围 | v1 只收 `sprite-sequence/v1` | 多 profile 并行 | 复杂宠物要等后续 profile |
| D5 | 身份归属 | `pet.json` 的 `id` + `version` 是唯一身份；`market.json` 只做展示并交叉校验 | 目录条目决定身份 | 目录条目可能过期 |
| D6 | 安装事务 | 解析 → 下载 → 三层校验 → 暂存 → 原子提交 → 注册 → 激活；失败回滚，保留一层旧版本 | 直接解到目标目录 | 多占一份旧版本空间 |
| D7 | 网络与磁盘位置 | 全在 Host 半；客户端只走 `/petmarket/api/*` 与 SSE | 客户端直连 GitHub | Host 半要承担代理职责 |
| D8 | 预览 | 预览不安装：临时目录 + `pets:renderers` 播 `idle` | 预览即安装 | 多一次解包 |
| D9 | 内核形态 | `core/*` 纯函数 + 端口注入（Github/Http/Fs/Store/Host/Clock/Event） | 直接调 DSH API | 多一层接口 |
| D10 | 数据根 | `ctx.fs` 数据目录 → `<cwd>/.petmarket` → 元数据降级到 `storageDomain` | 只用其中一种 | 降级路径要测 |
| D11 | 规范权威 | 规范正本在市场仓 `spec/`，宿主与模板 vendor 同一份 schema | 各仓自持一份 | 需要同步机制 |
| D12 | 标识 | 插件 id `petmarket`、路由 `/petmarket`、service `petmarket`、storageDomain `petmarket`；包名见 P7 | 用现有 scope | 命名待最终确认 |
| D13 | 宿主契约 | 只依赖 `pethost` 六方法 + 行为要求，不依赖任何宿主实现 | 直接对接某个宿主 | 宿主侧需要适配 |

## 2. 开放的产品选择

每条给推荐项与影响面。评审时勾选即可。

### P1 目录仓库的形态

| 选项 | 说明 | 影响 |
| --- | --- | --- |
| A（推荐）静态 `index.json` + PR | 一个 JSON，CI 校验 schema 与域名，合并即上线 | 可控、可 fork、可审计；需要有人看 PR |
| B GitHub topic 搜索 | 按 topic 搜仓库，无需维护索引 | 零维护；结果不可控，噪音大，限流压力大 |
| C issue 即提交 | 用 issue 表单收录，CI 转 JSON | 门槛低；状态与 JSON 双写，易漂移 |

推荐 A，B 作为「高级搜索」补充入口，C 不做。

### P2 prerelease 默认策略

| 选项 | 说明 | 影响 |
| --- | --- | --- |
| A（推荐）默认 `stable`，来源级可切 `prerelease` | 更新检查只认 `releases/latest` | 稳定；尝鲜要显式切 |
| B 默认收 prerelease | 更新更早 | 用户被半成品打扰 |
| C 目录条目声明频道 | 按条目走 | 目录维护成本上升 |

推荐 A。

### P3 包签名

| 选项 | 说明 | 影响 |
| --- | --- | --- |
| A（推荐）v1 不做签名，只做哈希链 | release digest + `checksums.json` + ledger 锁哈希 | 简单；无作者身份保证 |
| B 可选 Ed25519 分离签名 | 作者发布 `.sig`，目录条目带公钥指纹 | 可验证作者；密钥管理成本 |
| C 强制签名 | 不签不装 | 生态起步门槛过高 |

推荐 A，字段与流程先留位（`checksums.json` 里预留 `signatures`），B 作为 v1.1 可选增强。

### P4 单仓多包

| 选项 | 说明 | 影响 |
| --- | --- | --- |
| A（推荐）支持，但一次装一个 | release 挂多个 `.dsppet`，`resolve` 返回多候选 | 作者可做系列宠物；UI 要选资产 |
| B 一仓一包 | 强制一对一 | 简单；系列作者要开多仓 |

推荐 A。

### P5 UI 落点

| 选项 | 说明 | 影响 |
| --- | --- | --- |
| A（推荐）`settings.section` 主面板 + `shell.overlay` 进度气泡 | 与现有插件一致 | 依赖两个 slot |
| B 独立浮窗 | 更像商店 | 要自管窗口与关闭行为 |
| C 只做命令面板 | 最轻 | 浏览体验差 |

推荐 A。

### P6 图集格式

| 选项 | 说明 | 影响 |
| --- | --- | --- |
| A（推荐）PNG + WebP，sheet 与 frames 两种模式 | 覆盖绝大多数美术导出 | 校验器要解析两种头 |
| B 只 PNG | 最简单 | 包体积大 |
| C 允许 SVG 图集 | 矢量清晰 | 渲染与安全成本高 |

推荐 A；SVG 只允许做缩略图与截图。

### P7 包名与 scope

| 选项 | 说明 | 影响 |
| --- | --- | --- |
| A（推荐）仓库名 `dsh-pet-market`，插件 id `petmarket`，发布包名后续随生态定 | 不绑现有 scope | 需要一次命名确认 |
| B 沿用现有 `@dshpets/*` scope | 生态一致 | 与「市场独立于宿主」的定位略有牵扯 |
| C 全新 scope | 品牌独立 | 需要新组织与发布权限 |

推荐 A。市场与宿主是两个产品，包名解耦更利于换宿主。

### P8 默认预置目录源

| 选项 | 说明 | 影响 |
| --- | --- | --- |
| A（推荐）预置官方目录 URL，可删可换 | 开箱有内容 | 官方目录成为事实入口 |
| B 不预置，首次启动让用户填 | 完全中立 | 冷启动体验差 |

推荐 A，并在设置里明示「可删除，删除后仍可粘贴链接安装」。

### P9 同版本内容变化

| 选项 | 说明 | 影响 |
| --- | --- | --- |
| A（推荐）视为需确认的替换安装 | 显示「同版本内容变化」 | 作者改包不用发版；用户要确认 |
| B 直接拒绝 | 强制作者提版本号 | 严格；体验略硬 |

推荐 A。

## 4. 待确认的硬问题

这四条需要在进入实现前拍死，否则会反复：

1. **默认目录 URL 指向哪个组织**：官方目录仓库放哪、谁有合并权。
2. **宿主由谁提供**：市场自带一个最小宿主，还是只做市场、宿主另立项目。
3. **`petRuntime` 版本号起点**：`1.0.0` 对应哪一组能力（决定首批包是否支持非零 `margin`、`loop: false`）。
4. **数据根是否允许用户改**：默认 `<dataRoot>`，是否在设置里暴露路径选择。
